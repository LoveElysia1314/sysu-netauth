# Windows 睡眠与休眠恢复

自动恢复需要后台服务正在运行、已保存凭据，并启用“服务启动后自动认证”。手动断开后，唤醒不会自动重新连接。

## 恢复流程

休眠前后，网卡都可能显示已连接，但交换机上的认证会话已经失效，或原抓包句柄需要重新打开。服务通过 SCM 接收挂起和自动恢复事件，取消旧会话和联网探测，清除过期状态，等待两秒后重新打开抓包并认证。

唤醒后的失败沿用普通断线的重试规则：间隔从 3 秒开始逐步延长，达到配置上限后保持低频重试。未连接的网卡等待网络事件；驱动暂时不可用时继续尝试。没有收到挂起通知时，恢复事件仍会重置会话。前台 `--console` 模式不接收 SCM 电源控制通知。

## 排查方法

认证成功后退出 GUI，完成一次睡眠或休眠，再从管理员终端查看：

```powershell
sc.exe query SYSUNetAuth
sysu_netauth status --json
Get-Content "$env:ProgramData\SYSUNetAuth\service.log" -Tail 40
```

日志应出现新的认证尝试，联网成功后记录 `authenticated; Internet reachable`。服务未启动时检查 SCM 中的服务状态和启动类型；服务正在运行但认证失败时，检查原生驱动访问、网卡选择、凭据及联网探测结果。

设备回归检查包括睡眠、休眠、无人值守唤醒、网卡延迟就绪和重复恢复；测试步骤见[验证文档](VALIDATION.md)。
