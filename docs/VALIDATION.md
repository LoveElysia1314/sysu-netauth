# 测试与验证

协议与服务测试使用示例凭据和独立配置。Linux 集成测试在私有网络命名空间中创建虚拟网卡，验证认证、续期、恢复和网卡切换。

## 自动化检查

从仓库根目录执行：

```sh
cargo fmt --all --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
python -m unittest discover -s tests -v
```

Windows GUI 带提权清单，完整 Cargo 测试运行其测试程序时也需要管理员权限。普通终端可运行 `cargo test --locked --lib`，验证引擎、协议、配置、界面状态及原生控件。安装程序的权限和服务生命周期测试需要管理员权限，分别使用临时目录和独立命名的测试服务，完成后清理。

Linux 网络测试需要 iproute2、util-linux 和网络命名空间权限：

```sh
cargo test --locked --test linux_network -- --ignored --nocapture --test-threads=1
```

受限于非特权命名空间策略时，可仅提权测试程序：

```sh
CARGO_TARGET_X86_64_UNKNOWN_LINUX_GNU_RUNNER='sudo -n --' cargo test --locked --test linux_network -- --ignored --nocapture --test-threads=1
```

## 覆盖范围

- 认证、联网验证期间的续期、在线重新认证与认证端 MAC 变化。
- IPC 请求、订阅释放、直接操作互斥及服务停止。
- 模拟挂起/恢复和首个网卡联网失败后的候选切换。
- 统一重试退避、配置错误暂停重试，以及手动断开后插拔和唤醒仍保持断开。
- 隔离网络中立即验证连通性、短故障自动重连，以及网卡改名后按设备 ID 重新连接。
- 原生 Win32 下拉控件在插拔、重排和重命名后的选择保持。
- 连接通知的 5 秒防抖、持续中断与恢复提醒、主动连接和通知关闭。
- 正式版更新筛选、Beta 到正式版比较、缓存重算和镜像落后回退。
- 发行标签、附件完整性、架构一致性、校验值及安装辅助逻辑。
- Windows 安装时修复已有文件权限，新建日志与轮转日志继承仅 SYSTEM 和管理员可访问的权限。

网络命名空间测试不能代替校园交换机、Npcap 驱动和 Windows 电源事件的实机验证。联网探测沿系统路由发送，成功可能来自 Wi-Fi 等其他接口。

## 设备回归

| 场景 | 预期行为 |
| --- | --- |
| 安装后填写 NetID 与密码 | 界面连接服务并完成认证 |
| 退出 GUI，保留独立服务 | 服务继续响应交换机续期 |
| 反复睡眠、休眠或无人值守唤醒 | 服务重新打开抓包并认证 |
| 唤醒后网卡延迟就绪 | 服务在恢复窗口内继续尝试 |
| 插拔、重命名或重排网卡 | 列表刷新，尚未保存的选择保持对应设备 |
| 拔出所选网卡后保存 | 设备显示为未连接，不误存为其他设备 |
| 首个候选网卡联网验证失败 | 继续尝试剩余候选 |
| 手动断开或关闭自动认证后唤醒 | 保持断开 |
| 升级、取消升级与卸载 | 替换或删除文件前停止应用和服务 |
| 当前测试版遇到较低正式版或较新测试版 | 不提示降级或测试版更新 |
| 同版本正式版发布 | 测试版提示正式版更新 |

## 构建校验

Windows 发布构建会检查可执行文件架构、导入的运行库、GUI 图标和提权清单，再生成安装包。构建安装包不会修改本机已安装的服务。

```powershell
./scripts/build.ps1 -Target x86_64-pc-windows-msvc
```

各平台应分别完成对应的构建和测试；构建方法见[源码构建](BUILDING.md)。
