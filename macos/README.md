# macOS 原生 GUI（开发预览）

AppKit 窗口沿用 Windows 的“账户与连接 / 网络状态”双栏布局，支持 NetID、密码、手动选卡、重试间隔、自动认证、保存、重新连接、断开与刷新。使用系统颜色适配深浅主题。新增登录启动、登录时隐藏窗口、菜单栏常驻与状态通知；更新界面尚未移植。

## 构建与测试

构建需要 Rust stable、Xcode Command Line Tools（Swift 5.9+），标准 XCTest 需要完整 Xcode。无第三方 Swift 依赖：

```sh
swift test --package-path macos
sh scripts/test-macos-gui-offline.sh
sh scripts/build-macos-gui.sh
open dist/SYSUNetAuth.app
```

打包脚本同时构建 Rust CLI 与服务，并放入 `.app/Contents/Resources`，因此不再依赖预先安装 `/usr/local/bin/sysu_netauth`。构建失败时脚本退出，不能将缺少组件的包视为成功产物。应用包使用开发用 ad-hoc 签名，尚无 Developer ID 签名或公证，未纳入正式发行包。

仅有 Command Line Tools 时，独立离线检查不依赖 XCTest，覆盖 JSON 契约、参数隔离、模拟 CLI 成功/失败、超时、组件缺失、组件定位、shell 字面量转义和设置序列化。完整 XCTest 配置于 macOS GUI CI，CI 也构建 Rust 组件与应用包。

## 使用与授权

初次打开会读取本机网卡并通过 helper 尝试读取服务状态，不自动弹出授权框、不安装服务、不发送认证帧。尚未安装 helper 时会提示安装，网卡信息仍能展示。

点击“安装后台服务…”会先确认再由 macOS 请求管理员授权，安装现有 launchd 服务和 CLI。用户自行输入管理员密码，应用不会读取该密码。macOS 13+ 的刷新状态、保存设置、重新连接与断开由 XPC helper 调用原服务，保留原有 root-only IPC 校验，不需要以 root 运行整个 GUI；旧系统继续通过系统授权调用 CLI。

填写账号后，保存会导入后台服务配置；重新连接会先保存填写的账号再请求认证。留空账号时，重新连接使用服务已有配置。账号密码不写入命令行参数；helper 模式经 XPC 数据传送，旧 CLI 授权路径使用权限为 700 的临时目录和 600 的临时文件，调用结束后删除。服务按项目原有机制保存凭据。当前版本不回填已有账号配置，保存会采用界面设置及其余字段默认值。自动认证默认不勾选，避免离线开发时意外启动认证。

## 离线预览

无需后台服务，可用静态模拟 CLI 预览：

```sh
chmod +x macos/OfflineChecks/mock-cli.py
NETAUTH_CLI="$PWD/macos/OfflineChecks/mock-cli.py" \
  dist/SYSUNetAuth.app/Contents/MacOS/SYSUNetAuth
```

模拟接口、窗口标题与状态消息明确标注“模拟”。模拟模式的保存、连接、断开与安装按钮不会访问服务或保存凭据，状态始终为待机。

源码开发可通过 `NETAUTH_CLI` 指定 CLI 绝对路径；`NETAUTH_DATA_DIR` 对应 CLI 的 `--data-dir`。这些变量需从终端直接启动应用可执行文件时传入。

macOS 13+ 已加入 XPC helper，日常状态、保存、连接、断开不再调用 osascript。首次安装/更新仍需管理员授权。当前开发版沿用已有安装脚本注册 launchd Mach service，尚未接入 SMAppService 注册流程；macOS 11/12 和显式 CLI/私有目录开发覆盖继续使用原授权方式。

helper 由 root 运行，安装策略文件为 root:wheel 600，固定授权安装时的用户 UID 和 GUI 主程序 CDHash。系统 XPC 签名要求在消息分发前校验 GUI，GUI 也校验 helper CDHash。所有二进制采用 ad-hoc 签名及 hardened runtime；没有正式 Developer ID 签名或公证。每次 GUI/helper 代码变化后必须重新授权安装，不能据此声称正式发行安全审计已完成。

helper 仅开放 status、set_config、authenticate、logoff 四个动作，不执行外部命令、不接受路径、不开放凭据读取。配置仍由原 Rust 服务校验并保存，原 root-only socket、对端 root 校验保持不变。请求/响应最大 64 KiB、配置载荷最多 60000 字节、连接读写超时 5 秒、最多 8 个并发处理请求。签名不符时失败关闭，不自动弹出密码框兜底。

## 桌面功能

macOS 13+ 的“登录时启动程序”通过 SMAppService.mainApp 注册当前应用，勾选立即生效，与账号保存独立；“启动时隐藏窗口”只影响系统登录启动，手动打开仍显示窗口。系统拒绝或要求批准时会显示提示。macOS 11/12 暂不开放登录项开关。注册后请保持应用路径稳定；这轮未注销当前用户，真实重登行为仍待验证。

菜单栏始终显示状态图标，提供显示窗口、刷新、重新连接、断开和退出。关闭窗口只隐藏窗口并保留菜单栏，退出应用才结束 GUI，后台认证服务独立运行。菜单栏刷新每 5 秒读取一次 helper 状态，避开手动操作；后台轮询不禁用正在编辑的账号字段。旧系统不自动轮询，避免反复弹出授权框。

“状态变化时通知”主动请求系统通知权限，默认关闭。首次快照、相同状态不通知；认证成功间隔至少 180 秒，失败至少 300 秒，两者单独计时，与 Windows 版一致。通知只含通用状态，不展示账号、密码、网卡或后台错误文本。点击通知可显示主窗口。权限拒绝会提示去系统设置，授权等待中不会提前显示为已启用。

菜单栏的“发送离线测试通知”不联系认证服务，可用于检查授权和通知中心投递。专注模式、系统通知样式以及“共享屏幕时关闭通知”可能抑制横幅，应用不修改这些全局设置。隐藏窗口时，真实状态变化仍能产生通知；退出 GUI 后不产生桌面通知。

独立离线检查已扩充为 31 项，覆盖通知去重、独立冷却、禁用与初始快照，以及登录隐藏窗口的判断。完整 XCTest 仍需完整 Xcode，可由 CI 执行。

2026-11-03 桌面功能实测：登录项注册、注销和重新注册成功，登录项及通知偏好在 GUI 重开后保留；⌘W 隐藏窗口后进程仍运行，用户确认菜单栏菜单可用并可恢复窗口。系统通知权限已允许，离线测试通知经系统已投递列表确认成功。前台通知包含 banner、list 和 sound；系统屏幕共享设置可能抑制横幅，不将横幅缺失判作发送失败。新版 helper 已由用户授权更新，自动轮询恢复正常，不同签名客户端继续被拒绝。未注销或重启当前 macOS 会话，真实登录隐藏启动和真实校园网状态通知仍待验证。

## 菜单栏图标

菜单“菜单栏图标”提供单色（默认、跟随系统）和彩色（Windows 配色）两种样式，并在当前用户偏好中记忆。六个矢量图标统一保留盾牌：网口代表待命、双向箭头代表认证中、对勾代表已认证、叉号代表失败、横线代表主动断开/停止、感叹号代表服务不可用。色彩为蓝/橙/绿/红/灰，与 Windows 状态映射一致，同时提供不同符号、菜单文字及无障碍标签，避免只依赖颜色；菜单选中图标使用单色高对比样式。

图标为 AppKit 绘制的 18pt 矢量图，单色使用模板图像，彩色模式随菜单栏有效外观重绘。生成浅色、深色、选中状态及实际/放大尺寸预览：

```sh
swift run --package-path macos -c release NetAuthIconPreview dist/menu-bar-icons.png
```

离线检查现为 41 项，新增状态与 Windows 配色映射、未知状态及主动断开区别检查。Windows 现有托盘逻辑无需改变。
